1. What is a VM Extension?

A VM Extension is a small software agent that runs inside an Azure Virtual Machine after the VM has been created. It lets you install software, run scripts, and configure the machine — without logging in through RDP or SSH.

The VM gives you the machine. The Extension does the setup work on that machine — automatically, from the Azure Portal.

Common Extension Types

Extension What it does
Custom Script Extension Runs a PowerShell script (Windows) or Bash script (Linux) on the VM. Most widely used.
Run Command Runs a script immediately from the portal and shows the output on screen. Good for quick tasks and troubleshooting.
VM Access Extension Resets the VM password or SSH key when you are locked out.
Azure Monitor / Diagnostics Collects CPU, memory, disk metrics and logs from inside the VM.
Antimalware Extension Installs and enables Microsoft Antimalware on the VM.

2. Lab Objective

Create a Windows Server VM and install IIS Web Server on it using extensions — without ever connecting via RDP. We will do it in two ways:

Method Why we use it
Part A — Run Command Runs instantly and shows output in the portal. Confirms the script itself is correct.
Part B — Custom Script Extension The real extension. Attaches to the VM and can be reused in automation templates.

Estimated time: 30 minutes

4. Part A — Create the VM

1

Start VM creation

Open the Azure Portal, search for Virtual Machines, then click + Create → Azure virtual machine.

portal.azure.com → Virtual machines → + Create
2

Fill the Basics tab

Enter all the values from the configuration table in Section 3. For Size, click "See all sizes" and search for B2s.

3

Allow inbound ports

Still on the Basics tab, scroll to Inbound port rules → "Select inbound ports" → tick HTTP (80) and RDP (3389).

4

Create the VM

Click Review + create → Create. Deployment takes about 3–5 minutes. Wait until you see "Your deployment is complete", then click Go to resource.

Wait before continuing. After deployment finishes, give the VM another 2–3 minutes to finish booting. The Azure VM Agent inside the VM must be running before any extension can work.

5. Part B — Method 1: Run Command

This is the fastest way to run a script on a VM and see the result immediately. We use it first to confirm our script works.

5

Open Run command

In your VM's left menu, scroll to Operations → click Run command.

MyWinVM → Operations → Run command
6

Select RunPowerShellScript

From the list of commands, click RunPowerShellScript. A text box opens on the right side.

7

Paste the script and run it

Paste the script below into the box, then click Run. It takes 1–3 minutes. The output appears directly below the box.

Script 1 — Install IIS (paste into Run command)
# Install IIS Web Server with management tools Install-WindowsFeature -Name Web-Server -IncludeManagementTools # Remove the IIS default page so our own page is shown Remove-Item "C:\inetpub\wwwroot\iisstart.htm" -Force -ErrorAction SilentlyContinue # Create our own home page $page = "<html><body><h1>Hello from Azure VM Extension</h1><p>IIS was installed automatically.</p></body></html>" Set-Content -Path "C:\inetpub\wwwroot\index.html" -Value $page # Print confirmation Write-Output "IIS installation finished successfully."
Expected output in the portal
Success Restart Needed Exit Code Feature Result ------- -------------- --------- -------------- True No Success {Web-Server, ...} IIS installation finished successfully.
8

Test in the browser

Go to MyWinVM → Overview and copy the Public IP address. Open a new browser tab and visit http://<your-public-ip>.

MyWinVM → Overview → Public IP address
Checkpoint: The browser should show "Hello from Azure VM Extension". You have now configured a VM without ever using RDP.

6. Part C — Method 2: Custom Script Extension

Run Command is manual and one-time. The Custom Script Extension attaches permanently to the VM and can be included in automation templates, so the same setup repeats on every new VM.

Rule you must know: A VM can have only ONE Custom Script Extension at a time. If a previous attempt failed, you must delete the old extension first — otherwise every new attempt fails. This is the single most common reason this lab fails repeatedly.

Step 1 — Prepare the script file

9

Create install-iis.ps1 on your computer

Open Notepad, paste the script below, then choose File → Save As.

File name: install-iis.ps1  |  Save as type: All Files  |  Encoding: UTF-8

Encoding matters. Choose plain UTF-8, not "UTF-8 with BOM". A BOM adds hidden characters at the start of the file and PowerShell fails with exit code 1. Also make sure the file is saved as .ps1 and not install-iis.ps1.txt.
install-iis.ps1 — save this file
# install-iis.ps1 # Azure Custom Script Extension - installs IIS and a custom home page # Install IIS Web Server Install-WindowsFeature -Name Web-Server -IncludeManagementTools # Remove IIS default page Remove-Item "C:\inetpub\wwwroot\iisstart.htm" -Force -ErrorAction SilentlyContinue # Create custom home page $page = "<html><body><h1>Deployed by Custom Script Extension</h1><p>Server: " + $env:COMPUTERNAME + "</p></body></html>" Set-Content -Path "C:\inetpub\wwwroot\index.html" -Value $page # Write a log file we can check later Add-Content -Path "C:\extension-log.txt" -Value ("IIS installed at " + (Get-Date)) Write-Output "Custom Script Extension completed."

Step 2 — Attach the extension

10

Open Extensions and clean up first

Go to MyWinVM → Settings → Extensions + applications.

If a CustomScriptExtension is already listed (from a previous attempt), select it and click Uninstall. Wait until it disappears from the list before continuing.

MyWinVM → Settings → Extensions + applications
11

Add the Custom Script Extension

Click + Add → search for and select Custom Script Extension → click Next.

12

Upload the script file

In the Script file field, click Browse and select your install-iis.ps1 file. Leave Arguments empty.

Click Review + create → Create.

13

Watch the status

The status moves through Transitioning → Provisioning succeeded. This takes 2–5 minutes. Refresh the page if the status seems stuck.

Step 3 — Read the extension output

14

View detailed status

Click on CustomScriptExtension in the list, then click View detailed status. This shows the actual script output (stdout) and any error messages (stderr).

This is the screen you must check whenever an extension fails.

Expected detailed status
Status: Provisioning succeeded [stdout] Custom Script Extension completed. [stderr] (empty)
15

Verify in the browser

Visit http://<your-public-ip> again. The page should now read "Deployed by Custom Script Extension" and show the server name.

Lab complete. You installed and configured IIS on a Windows VM twice — once with Run Command and once with the Custom Script Extension — without using RDP at any point.

7. Troubleshooting — Why the Extension Fails

Symptom Cause Fix
Every retry fails, even after fixing the script An old Custom Script Extension is still attached. Only one is allowed per VM. Extensions + applications → select the old one → Uninstall → wait → add again
Status: Failed, "exit code 1" Script saved with UTF-8 BOM, or saved as .txt Re-save in Notepad: type All Files, encoding UTF-8, name ending in .ps1
Install hangs, times out, or VM becomes unresponsive VM size too small — B1s has only 1 GB RAM Resize the VM to Standard_B2s (4 GB RAM), restart, retry
"Install-WindowsFeature is not recognized" Wrong image — Server Core or a Windows client image was selected Use Windows Server 2022 Datacenter : Azure Edition (Gen2)
Status succeeded, but browser does not load Port 80 not allowed in the Network Security Group VM → Networking → Add inbound rule → Port 80, TCP, Allow, priority 100
Browser shows the blue IIS default page index.html was not written, or iisstart.htm still exists Run Command → Get-ChildItem C:\inetpub\wwwroot to check which files are present
Status stuck on "Transitioning" for a long time Azure VM Agent not ready — the VM is still booting Wait 5 minutes, then restart the VM and check Boot diagnostics
Browser shows "connection timed out" VM is stopped or deallocated VM → Overview → check status is Running; click Start if needed
First thing to check, always: Extensions + applications → click the extension → View detailed status. The real error message is there. Do not guess.

8. Run Command vs Custom Script Extension

Feature Run Command Custom Script Extension
Output visible in portal Yes — immediately Only via "View detailed status"
Stays attached to the VM No Yes
Can be reused in automation / ARM templates No Yes
How many allowed per VM Unlimited, run any number of times Only one at a time
Best used for Quick fixes and troubleshooting Repeatable deployment configuration
