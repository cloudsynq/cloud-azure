Azure Managed Disks

Cloud Computing · Unit: Azure Compute & Storage

1. What is a Managed Disk?

An Azure Managed Disk is a virtual hard drive (VHD) in the cloud. Just like your laptop has a hard drive (HDD or SSD) to store the OS and files, an Azure Virtual Machine (VM) needs a disk to store its operating system, applications, and data.

The word "Managed" means Azure automatically handles all the storage infrastructure for you — replication, availability, capacity — you just choose the size and type.

Analogy
Think of a Managed Disk as a pen drive that you buy online — Amazon stores it, ships it to you, and you just plug it in. You don't worry about how it was manufactured or stored. Azure Managed Disk = Azure manages the storage, you just attach it to your VM.

2. Three Types of Disks on an Azure VM

Every Azure VM has up to three different types of disks attached to it:

OS Disk
Contains the operating system (Windows or Linux). Created automatically when VM is created. Usually 30–128 GB.
Temporary Disk
Small, fast disk for temporary files. Data is LOST on reboot/deallocation. Mounted as /dev/sdb or D:\ automatically.
Data Disk (Managed)
Extra disk you attach manually for storing your own data. Persistent — data stays even after reboot. You format and mount it yourself.
Critical Point — Temporary Disk
The temporary disk (/dev/sdb1 on Linux, D:\ on Windows) is NOT persistent. Any data stored here is lost when the VM is stopped/deallocated or resized. Never store important data here. It is meant for page files, swap space, or truly temporary files.

How to Identify Disks (Linux — lsblk command)

$ lsblk NAME MAJ:MIN RM SIZE RO TYPE MOUNTPOINT sda 8:0 0 30G 0 disk ← OS Disk (boot disk) ├─sda1 8:1 0 29.9G 0 part / └─sda15 8:15 0 105M 0 part /boot/efi sdb 8:16 0 75G 0 disk ← Temporary Disk (DO NOT use for data) └─sdb1 8:17 0 75G 0 part /mnt sdc 8:32 0 128G 0 disk ← Your Managed Data Disk (attached manually)
Rule of Thumb
When you attach a new managed disk, it shows up as sdc (or nvme0n2 on newer VMs). It has no partition, no filesystem, no mount point — you must format and mount it yourself before using it.

4. Managed Disk — Attach & Use Workflow

After creating and attaching a managed disk to a VM, you follow these steps inside the VM (Linux):

Azure Portal ┌──────────────────┐ │ Create Disk │ → Choose SKU, Size, Region │ Attach to VM │ → VM → Disks → + Add data disk └──────────────────┘ │ ▼ SSH into VM ┌──────────────────────────────────────────┐ │ Step 1: Find the disk │ │ $ lsblk │ │ (new disk shows as sdc with no mount) │ │ │ │ Step 2: Format the disk │ │ $ sudo mkfs.ext4 /dev/sdc │ │ (creates ext4 filesystem on disk) │ │ │ │ Step 3: Create mount point directory │ │ $ sudo mkdir /mnt/mydata │ │ │ │ Step 4: Mount the disk │ │ $ sudo mount /dev/sdc /mnt/mydata │ │ │ │ Step 5: Verify │ │ $ df -h │ │ (disk should appear in the list) │ │ │ │ Step 6: Make mount permanent (fstab) │ │ $ sudo nano /etc/fstab │ │ → add: /dev/sdc /mnt/mydata ext4 defaults 0 0 └──────────────────────────────────────────┘

5. /etc/fstab — Making Mount Permanent

By default, mount command works only until VM reboots. To make the disk auto-mount every time VM starts, you add an entry to /etc/fstab.

# Format of /etc/fstab entry: # <device> <mount-point> <type> <options> <dump> <pass> /dev/sdc /mnt/mydata ext4 defaults 0 0 # Meaning of each field: /dev/sdc ← which disk /mnt/mydata ← where to mount it ext4 ← filesystem type defaults ← standard mount options 0 0 ← don't dump, don't fsck at boot
Warning — fstab Mistakes
A wrong entry in /etc/fstab can prevent the VM from booting. Always verify your fstab entry with sudo mount -a (test all fstab entries without rebooting) before restarting the VM.

6. Azure Disk Snapshots

A Snapshot is a point-in-time backup (read-only copy) of a managed disk. It captures the exact state of the disk at that moment.

Analogy
Snapshot is like taking a photograph of your disk. The original disk can still change, but the snapshot preserves the state from when the photo was taken. If anything goes wrong later, you can restore from the snapshot.

When to use Snapshots

  • Before doing a risky update or configuration change on the OS
  • Before migrating a VM to a different region
  • As a backup before a major application upgrade
  • For disaster recovery — restore VM if OS crashes

Snapshot → Disk → VM Recovery Flow

OS Disk (current state) │ ▼ Take Snapshot ┌─────────────────────┐ │ Snapshot (backup) │ ← Read-only point-in-time copy └─────────────────────┘ │ ▼ If OS crashes → Create New Disk from Snapshot ┌─────────────────────┐ │ New Managed Disk │ ← Restored from snapshot └─────────────────────┘ │ ▼ Swap VM's OS Disk ┌─────────────────────┐ │ VM (recovered) │ ← Now runs from restored disk └─────────────────────┘

Snapshot Types

TypeDescription
Full SnapshotComplete copy of entire disk. Larger size, higher cost.
Incremental SnapshotSaves only changes since last snapshot. Smaller, cheaper. Recommended for regular backups.
Best Practice
Use Incremental Snapshots for regular backups — they are much cheaper and smaller since they only store what changed since the last snapshot.

7. Resizing a Managed Disk

You can increase the size of a managed disk at any time from Azure Portal — but you cannot decrease it.

Steps to Resize

  1. Stop (deallocate) the VM — required for OS disk; optional for data disk
  2. Azure Portal → Disk → Size + Performance → change size → Save
  3. Restart VM
  4. Inside VM — extend the partition using growpart and resize2fs commands
# After resizing disk in Azure Portal, inside the VM: sudo growpart /dev/sdc 1 # extend partition sudo resize2fs /dev/sdc1 # resize filesystem to fill new space df -h # verify new size

9. Important Exam Points

  • Managed Disk = Azure manages storage; you just attach to VM. Better than Unmanaged Disks.
  • 3 disk types on a VM: OS Disk (persistent), Temporary Disk (data lost on reboot), Data Disk (persistent, attached manually).
  • 4 SKUs: Standard HDD (cheap) → Standard SSD → Premium SSD (most common in prod) → Ultra Disk (highest performance).
  • lsblk = see all disks. df -h = see mounted disks with space.
  • mkfs.ext4 = format disk (like formatting a new pen drive).
  • mount = attach disk to folder. Without fstab, mount is lost after reboot.
  • /etc/fstab = Linux config file for automatic mount at boot.
  • Snapshot = point-in-time backup. Use Incremental for regular backups (cheaper).
  • To recover from OS crash: Snapshot → New Disk → Swap OS disk on VM.
  • Disk size can be increased but NOT decreased.
  • Temporary disk path on Linux = /dev/sdb or /mnt. Never store important data here.
