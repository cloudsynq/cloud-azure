Azure Storage Replication (Redundancy)

Cloud Computing · Module 4: Azure Storage

1. Why Does Azure Replicate Your Data?

When you store a file in Azure Storage, Azure does NOT keep just one copy. It automatically stores multiple copies in different locations to protect against:

  • Hard disk failure in a server
  • Power outage or fire in a data center
  • Earthquake, flood, or natural disaster in an entire city/region

This is called Storage Replication or Storage Redundancy. You choose the replication level when creating a Storage Account — it cannot be easily changed later without planning.

Analogy
Replication = making backup photocopies of an important document. LRS = 3 copies in the same drawer. GRS = 3 copies in your city + 3 copies in another city far away. More copies = more safety, but also more cost.

2. The 4 Replication Types — Explained

LRS — Locally Redundant Storage 3 copies

Full form: Locally Redundant Storage

Where stored: 3 copies, all in the same data center (same building, same city)

  • Cheapest option
  • Protects against: single disk failure, single server failure
  • Does NOT protect against: entire data center fire, earthquake
  • Availability: 99.999999999% (11 nines) within one data center

Best for: Dev/test environments, non-critical data, temporary files

ZRS — Zone Redundant Storage 3 copies

Full form: Zone Redundant Storage

Where stored: 3 copies, each in a different Availability Zone in the same region (different buildings, same city)

  • Protects against: entire data center failure (one zone goes down)
  • Does NOT protect against: entire region disaster (city-level)
  • High availability within one Azure region
  • More expensive than LRS

Best for: Production apps that need high availability within a region

GRS — Geo Redundant Storage 6 copies

Full form: Geo Redundant Storage

Where stored: 3 copies in primary region (LRS) + 3 copies in a paired secondary region hundreds of miles away

  • Protects against: complete regional disaster (earthquake, flood)
  • Secondary region: read-only during failover (not normally readable)
  • Significantly more expensive than LRS
  • RPO: typically under 15 minutes (replication lag)

Best for: Critical business data, compliance requirements, disaster recovery

RA-GRS — Read-Access GRS 6 copies

Full form: Read-Access Geo Redundant Storage

Where stored: Same as GRS (6 copies across 2 regions), but the secondary region is always readable — even without failover

  • Secondary endpoint always available for read operations
  • Endpoint format: accountname-secondary.blob.core.windows.net
  • Most expensive standard option
  • Best SLA for availability

Best for: Global apps needing read access from multiple locations

5. Azure Region Pairs (for GRS/RA-GRS)

When you use GRS or RA-GRS, Azure automatically replicates data to the paired region. You cannot choose the secondary region — Azure decides it based on geography and compliance:

Primary RegionPaired Secondary Region
Central India (Pune)South India (Chennai)
East US (Virginia)West US (California)
UK South (London)UK West (Cardiff)
West Europe (Netherlands)North Europe (Ireland)
Important
The secondary region in GRS is geographically distant (typically 500+ km away) to ensure even a regional disaster like an earthquake won't affect both locations simultaneously.

6. How to Set Replication in Azure Portal

  1. Go to Azure Portal → Search "Storage accounts" → Create new
  2. Under Redundancy dropdown, choose: LRS / ZRS / GRS / RA-GRS
  3. Note: if you select GRS/RA-GRS, you'll see "Make read access to data available in the event of regional unavailability" checkbox — checking this = RA-GRS
  4. You can change replication type later: Storage Account → Configuration → Replication
Portal Tip
In the Azure Portal, the dropdown shows: "Locally-redundant storage (LRS)", "Zone-redundant storage (ZRS)", "Geo-redundant storage (GRS)", "Read-access geo-redundant storage (RA-GRS)". For GRS, there is a checkbox to enable read access to the secondary region — checking it makes it RA-GRS.

7. Important Exam Points

  • LRS = 3 copies, 1 data center, cheapest. Does NOT protect against data center failure.
  • ZRS = 3 copies, 3 availability zones (different buildings), same region.
  • GRS = 6 copies, 2 geographic regions. Secondary is read-only, only during failover.
  • RA-GRS = Same as GRS but secondary is always readable via a separate endpoint.
  • RA-GRS secondary endpoint: accountname-secondary.blob.core.windows.net
  • Replication type is set at Storage Account level — applies to all services (Blob, Files, Tables, Queues).
  • Geo-replication is asynchronous — there may be a small lag (RPO). Data at secondary may be slightly older than primary.
  • Microsoft decides the paired region for geo-replication — you cannot choose.
  • More copies = higher durability = higher cost.
  • For exam: remember LRS→ZRS→GRS→RA-GRS as increasing protection and increasing cost.
