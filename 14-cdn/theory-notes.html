Azure Content Delivery Network (CDN)

BCA 3rd Semester · Cloud Computing · Unit: Azure Storage Services

1. What is a CDN?

A Content Delivery Network (CDN) is a distributed network of servers placed at multiple locations around the world. Its job is to deliver content (web pages, images, videos, files) to users faster by serving it from a server that is physically closest to them.

Analogy
Imagine you are in Delhi and you order a book from Amazon. If Amazon sends it from a warehouse in the USA, it takes 2 weeks. But if Amazon has a warehouse in Delhi itself, it arrives the next day. CDN works the same way — it keeps a copy of your website content in data centers near your users.

Without CDN vs With CDN

Without CDN
  • All users connect to ONE origin server
  • Users far away face high latency
  • Heavy load on origin server
  • Slow loading in other countries
  • No protection against traffic spikes
With CDN
  • Content cached at edge servers worldwide
  • Users get content from nearest location
  • Origin server handles less traffic
  • Fast loading globally
  • Handles traffic spikes easily

2. How Does Azure CDN Work?

Key Terms

  • Origin Server: Your actual server or Azure Storage account where files live.
  • Edge Server / PoP: CDN server placed at a geographic location (Point of Presence). Stores cached copies of your content.
  • Cache: Temporary copy of your content stored at the edge server.
  • TTL (Time to Live): How long content stays cached at the edge before it is refreshed from origin.
  • CDN Endpoint: The public URL provided by Azure CDN (e.g., mysite.azureedge.net) that users access.
  • CDN Profile: Container for one or more CDN endpoints. You define the CDN provider here.

Request Flow

User (Mumbai) requests mysite.azureedge.net/image.jpg │ ▼ Azure CDN routes to nearest PoP (e.g., Mumbai PoP server) │ ├─ CACHE HIT? → Serve directly from PoP ✓ (fast, ~5ms) │ └─ CACHE MISS? → Fetch from Origin (Azure Storage) → Store copy at PoP → Serve to user ✓ (first request only is slow)
Cache Hit
Content already stored at the edge server. Served instantly. No request goes to origin. This is the ideal case.
Cache Miss
Content not yet at edge. CDN fetches from origin, caches it, then serves user. Happens only on the first request after cache expires.

4. Azure CDN Key Features

Caching Rules

You can control how long CDN caches your content using TTL (Time to Live):

  • Global caching rule: Applies to all URLs on the endpoint.
  • Custom caching rule: Different TTL for specific file types (e.g., cache images for 7 days, HTML for 1 hour).
  • Query string caching: Cache differently based on URL query parameters.

HTTPS Support

Azure CDN provides a free TLS/SSL certificate for CDN endpoints (*.azureedge.net). You can also bring your own custom domain with HTTPS.

Custom Domain

Instead of mysite.azureedge.net, you can use your own domain like www.mycompany.com by adding a CNAME record in your DNS.

Compression

Azure CDN can automatically compress files (gzip/brotli) before sending them to users. This reduces file size by 50–70%, making pages load faster.

Geo-Filtering

Block or allow content delivery to specific countries. Useful for legal or licensing reasons.

Purge (Cache Invalidation)

When you update your website files, old cached content may still be served. You can purge (forcefully delete) the cache so CDN fetches the latest version from origin.

6. Azure Storage Static Website + CDN

The most common beginner use case is combining Azure Blob Static Website with Azure CDN:

Azure Blob Storage ┌─────────────────────────────────┐ │ Static Website: ENABLED │ │ Primary endpoint: │ │ https://xyz.z13.web.core... │ ← Origin │ │ │ $web container │ │ ├── index.html │ │ ├── style.css │ │ └── logo.png │ └─────────────────────────────────┘ │ ▼ CDN pulls from here ┌─────────────────────────────────┐ │ Azure CDN Profile │ │ CDN Endpoint: mysite.azureedge.net │ │ Origin = Static Website URL │ └─────────────────────────────────┘ │ ┌────────┴────────┐ ▼ ▼ Mumbai PoP London PoP (serves India) (serves Europe)

Why add CDN to a static website?

  • Static website URL is region-specific (e.g., East US only). CDN makes it global.
  • CDN provides free HTTPS — static website HTTP can be upgraded.
  • CDN reduces load on storage account during traffic spikes.
  • CDN provides better performance metrics and analytics.
  • Custom domain support is easier with CDN endpoint.

9. Important Exam Points

  • CDN stores cached copies at edge servers — not the original files.
  • The original file location is called the origin.
  • CDN reduces latency because it serves from the nearest PoP.
  • If content changes at origin, old cache still serves until TTL expires or you purge.
  • Azure CDN Standard from Microsoft is the default choice for static websites.
  • CDN endpoint URL format: https://<endpoint-name>.azureedge.net
  • Static website origin URL (not the blob URL, but the web endpoint): https://<account>.z13.web.core.windows.net
  • CDN helps with HTTPS for custom domains on Azure Static Websites.
  • Purge = force refresh; does NOT delete files from origin — only clears edge cache.
  • CDN charges are based on data transfer out from PoP locations.
