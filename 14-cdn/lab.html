After this lab you will have two working URLs for the same website — one direct from Storage, one via CDN.

1
Create Storage Account
Set up the container that will hold your website files
1
Open Azure Portal

Go to portal.azure.com → Sign in with your Azure account.

2
Search for Storage Accounts

In the top search bar, type Storage accounts → click it → click + Create.

3
Fill in Basic Settings
FieldValue
SubscriptionYour Azure subscription
Resource GroupClick Create new → name it cdn-lab-rg
Storage account namemycdnlab2026 (must be globally unique — add your name if taken, e.g. mycdnlabsahil)
RegionCentral India or East US
PerformanceStandard
RedundancyLRS (Locally Redundant Storage)

Click Review + Create → Create. Wait for deployment (~30 seconds).

4
Go to the Storage Account

After deployment: click Go to resource.

2
Enable Static Website Hosting
Turn your storage account into a web server
1
Find Static Website Setting

In your Storage Account left menu → scroll down to Data management section → click Static website.

2
Enable and Configure
  • Toggle: Enabled
  • Index document name: index.html
  • Error document path: error.html (optional, leave blank for now)

Click Save.

After saving — note these two URLs
Primary endpoint: https://mycdnlab2026.z29.web.core.windows.net/
This is your Static Website URL (direct from storage). Save it somewhere.
Note
Azure also created a special container called $web — this is where you will upload your website files.
3
Create Your Website File (index.html)

On your own laptop/PC, create a file called index.html and paste this code into it:

index.html — create this file on your laptop
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>My Azure CDN Website</title>
  <style>
    body { font-family: Arial, sans-serif; text-align: center; padding: 60px; background: #f0f4f8; }
    h1 { color: #0078D4; font-size: 40px; }
    p  { font-size: 18px; color: #444; }
    .box { background: white; border-radius: 12px; padding: 40px; display: inline-block; box-shadow: 0 4px 20px rgba(0,0,0,.1); }
  </style>
</head>
<body>
  <div class="box">
    <h1>Hello from Azure! ☁️</h1>
    <p>This website is hosted on <strong>Azure Blob Storage</strong></p>
    <p>Delivered globally by <strong>Azure CDN</strong></p>
    <p style="color:#888;font-size:14px">Lab by · Cloud Computing</p>
  </div>
</body>
</html>
4
Upload index.html to $web Container
  • In Storage Account left menu → Data storage → Containers
  • Click on the $web container (created automatically)
  • Click Upload (top button)
  • Click the folder icon → select your index.html file
  • Click Upload
After Upload
Open the Primary endpoint URL you saved in Step 2. You should see your website! If you see the page with "Hello from Azure!" — static website is working.
3
Create Azure CDN Profile + Endpoint
Connect CDN to your static website as the origin
1
Go to Azure Front Door and CDN

In top search bar → search Front Door and CDN profiles → click it → click + Create.

2
Choose "Explore other offerings"

On the "Compare offerings" page:

  • Select Explore other offerings
  • Select Azure CDN Standard from Microsoft (classic)
  • Click Continue
Why this option?
"Microsoft (classic)" is the simplest CDN tier — perfect for lab. Front Door is more advanced and expensive.
3
Fill CDN Profile Details
FieldValue
SubscriptionYour subscription
Resource groupcdn-lab-rg (same as before)
Name (Profile)mycdnprofile
Pricing tierMicrosoft CDN (classic)
Create a new CDN endpointCheck this checkbox ✓
4
Fill CDN Endpoint Details
FieldValue
CDN endpoint namemycdnlab (must be globally unique → results in mycdnlab.azureedge.net)
Origin typeCustom origin
Origin hostnamePaste your Static Website primary endpoint — without https://
Example: mycdnlab2026.z29.web.core.windows.net
Important
In Origin hostname — use the Static Website URL (z29.web.core...) NOT the blob storage URL (blob.core...). If you use the blob URL, CDN won't serve the files correctly.

Click Review + Create → Create.

Deployment time
CDN profile creates in ~2 minutes. But CDN endpoint propagation takes 10–30 minutes to go live globally. Be patient!
4
Test Both URLs
Verify static website and CDN endpoint both work
1
Get Your CDN Endpoint URL

Go to Front Door and CDN profiles → click mycdnprofile → in left menu click Endpoints → click your endpoint mycdnlab.

Note the Endpoint hostname: https://mycdnlab.azureedge.net

2
Wait for CDN Propagation (10–30 min)

CDN needs time to propagate to all edge servers. Check CDN status:

  • Go to your CDN endpoint → look for Running status
  • If status shows Starting — wait a few more minutes
If CDN URL gives 404
This is normal for the first 10–30 minutes. CDN is still propagating. Go get a chai and come back.
3
Open Both URLs in Browser

Try both of these in your browser:

# Direct Static Website URL (from Azure Storage) https://mycdnlab2026.z29.web.core.windows.net/ # CDN Endpoint URL (served via edge servers) https://mycdnlab.azureedge.net/
Expected Result
Both URLs should show the same "Hello from Azure!" page. Both are working correctly!
4
Check Response Headers (optional but impressive)

Open browser DevTools (F12) → Network tab → reload page → click on the main request → look at Response Headers:

  • On CDN URL: look for X-Cache: HIT or X-Cache: MISS — this tells you if content came from cache
  • First request = MISS (fetching from origin), second request = HIT (from edge cache)
5
Bonus — Update Website & Purge CDN Cache
See how to update content and force CDN to refresh
1
Update Your index.html

On your laptop, edit index.html — change the heading to something new:

<h1>Hello from Azure CDN! Updated! 🚀</h1>

Save the file → upload it again to $web container (same process as before, overwrite existing).

2
Check Direct URL vs CDN URL

Open both URLs:

  • Static Website URL → shows updated heading immediately ✓
  • CDN URL → still shows OLD content (because edge cache hasn't expired yet)

This shows why purge is needed when you update content!

3
Purge CDN Cache

Go to Front Door and CDN profiles → mycdnprofile → left menu → Endpoints → click mycdnlab → top menu click Purge.

  • Content path: type /* (purge everything) or /index.html (purge specific file)
  • Click Purge

Wait ~2–3 minutes → reload CDN URL → now shows updated content ✓

Key Learning
Purge = tells CDN to delete old cached version and fetch fresh content from origin. Used whenever you update your website files.
6
Cleanup — Delete All Resources
Always delete after lab to avoid charges
Important
Azure CDN and Storage accounts have ongoing costs. Delete resources after lab to avoid unexpected charges.
1
Delete via Resource Group (easiest method)

Go to Resource groups → click cdn-lab-rg → click Delete resource group (top button) → type the resource group name to confirm → click Delete.

This deletes everything inside: Storage Account, CDN Profile, and CDN Endpoint in one go.

2
Alternatively — Azure Cloud Shell
# Open Cloud Shell in Azure Portal (top bar > icon) az group delete \ --name cdn-lab-rg \ --yes \ --no-wait # --yes = no confirmation prompt # --no-wait = runs in background
3
Verify Deletion

Go to Resource groups — confirm cdn-lab-rg is gone. Go to Storage accounts — confirm mycdnlab2026 is gone.

Lab Complete!
You have successfully hosted a static website on Azure Blob Storage and connected it to Azure CDN for global fast delivery.
