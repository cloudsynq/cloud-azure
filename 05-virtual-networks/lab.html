Azure Virtual Networks — Hands-On Lab

BCA 3rd Semester · Cloud Computing · Public Subnet + Private Subnet + NSG + Bastion

What We'll Build Today

Resource Group: rg-vnet-lab └── VNet: MyVNet (10.0.0.0/16) ├── Public-Subnet (10.0.1.0/24) │ ├── VM-Public (Public IP: 20.x.x.x) ← SSH from Internet │ └── NSG-Public (Allow: SSH 22, HTTP 80) │ └── Private-Subnet (10.0.2.0/24) ├── VM-Private (No Public IP) ← Only reachable from VM-Public └── NSG-Private (Allow: SSH 22 from VNet only) Internet → VM-Public (20.x.x.x) → VM-Private (10.0.2.x) (private IP only)

Kya sikhenge: VNet creation, Subnets (public/private), IP addressing, NSG inbound/outbound rules, VM deployment in specific subnet, private connectivity testing, Azure Bastion.

1
Resource Group & VNet Create karo
~10 min · Azure Portal
1
Resource Group banao

Portal → Resource groups → Create → Name: rg-vnet-lab → Region: Central India → Create

2
VNet Create karo

Search → Virtual networks → Create

FieldValue
NameMyVNet
Resource Grouprg-vnet-lab
RegionCentral India
Address space10.0.0.0/16 (65,536 IPs)
Address Space kya hai?
10.0.0.0/16 matlab pehle 2 octets fixed (10.0) aur baaki 65,536 IP addresses available. Iske andar hum subnets banaenge.
3
Default subnet delete karo, do nayi banao

VNet create ke time IP Addresses tab mein jaao → default subnet delete karo → + Add subnet:

Subnet NameAddress RangeType
Public-Subnet10.0.1.0/24 (256 IPs)Internet-accessible VMs
Private-Subnet10.0.2.0/24 (256 IPs)Internal VMs only
Subnet kya karta hai?
VNet ko chhote pieces mein divide karta hai. Public subnet mein woh VMs jate hain jinhein internet access chahiye. Private subnet mein woh jate hain jo sirf andar se accessible hone chahiye (database, backend).
2
NSG — Network Security Group banao
~10 min · Firewall rules likhna
1
NSG for Public Subnet

Search → Network security groups → Create → Name: NSG-Public → rg-vnet-lab → Central India → Create

NSG open karo → Inbound security rules → + Add:

RuleSourcePortProtocolActionPriority
Allow-SSHAny22TCPAllow100
Allow-HTTPAny80TCPAllow110
Priority kya hai?
Chhota number = higher priority. Rule 100 pehle apply hoga rule 200 se. Default deny-all rule ka priority 65500 hota hai — sab kuch automatically block rahega jo tune allow nahi kiya.
2
NSG for Private Subnet

NSG create karo: Name: NSG-Private → Inbound rule add karo:

RuleSourcePortActionPriority
Allow-SSH-from-VNetVirtualNetwork22Allow100
Source = VirtualNetwork
Iska matlab sirf VNet ke andar se SSH allow hai — internet se koi directly private VM ko access nahi kar sakta. Yahi public aur private subnet ka fark hai!
3
NSG ko Subnet se associate karo

NSG-Public open karo → Subnets → Associate → MyVNet → Public-Subnet

NSG-Private open karo → Subnets → Associate → MyVNet → Private-Subnet

Done!
Ab NSG ke rules automatically subnet ke saare VMs pe apply honge.

4
Connectivity Test karo
~10 min · SSH se prove karo
1
Public VM mein SSH karo (internet se)
ssh azureuser@<VM-Public-IP> # Example: ssh azureuser@20.204.55.100
Connected!
Public VM internet se accessible hai — NSG ne port 22 allow kiya tha.
2
Private VM ka Private IP pata karo

Portal mein VM-Private jaao → Overview → Private IP address note karo (10.0.2.x)

3
Public VM se Private VM ko SSH karo (private IP use karo)

Public VM ke terminal mein (abhi bhi connected ho):

ping 10.0.2.4 # private VM ko ping karo → reply aayega! ssh azureuser@10.0.2.4 # private VM mein login karo
Key Learning!
Public VM → Private VM: WORKS (same VNet mein hain)
Internet → Private VM directly: BLOCKED (no public IP + NSG restricts to VirtualNetwork only)
Internet se test karo
Apne laptop se directly ssh azureuser@10.0.2.4 try karo → Connection refused/timeout — private VM internet se accessible nahi hai!
4
Hostname se ping karo (Azure DNS test)

VM-Public ke terminal se:

ping vm-private.internal.cloudapp.net # Azure DNS auto-resolves this # ya simply: nslookup vm-private # private DNS naam resolve hoga
Azure DNS
Azure automatically same VNet ke VMs ko ek-dusre ke naam se resolve kar deta hai — manually kuch configure nahi karna padta. Yahi Azure DNS hai.
5
Bonus: Azure Bastion — Secure SSH without Port 22
Optional · ~10 min

Problem: Port 22 khula rakhna risky hai. Bastion ek managed jump server hai jo browser se directly SSH karta hai — port 22 internet ke liye band kar sakte ho.

1
AzureBastionSubnet banao

MyVNet → Subnets → + Subnet → Name: AzureBastionSubnet (exact name chahiye) → Range: 10.0.3.0/26 → Save

Important
Subnet ka naam exactly AzureBastionSubnet hona chahiye — kuch aur naam nahi chalega.
2
Bastion Deploy karo

Search → Bastions → Create → rg-vnet-lab → MyVNet → Create new Public IP → Create

(10-15 min lagta hai deploy hone mein)

3
Bastion se VM Connect karo

VM-Private jaao → Connect → Bastion → Username + Password → Connect → Browser mein terminal khul jaayega!

Result
Private VM mein connect ho gaye — bina port 22 khole, bina public IP ke! Yahi Bastion ka fayda hai.

Exam Points — Ye zaroor yaad rakho

  • VNet = Azure ka apna private network. Internet se isolated by default.
  • Address Space: VNet ka total IP range (e.g. 10.0.0.0/16 = 65,536 IPs).
  • Subnet: VNet ka chhota hissa. Ek subnet ek zone jaisa hai.
  • Public Subnet: Public IP wale VMs. Internet-facing.
  • Private Subnet: No public IP. Sirf VNet ke andar se accessible.
  • NSG: Firewall rules. Inbound (aane wali traffic) + Outbound (jaane wali traffic).
  • NSG priority: chhota number = pehle apply. 65500 = deny all (default last rule).
  • Azure DNS: Same VNet ke VMs automatically ek-dusre ko naam se resolve kar sakte hain.
  • Azure Bastion: Port 22 khole bina browser se secure SSH. AzureBastionSubnet zaruri hai.
  • Same VNet ke VMs ek-dusre se private IP se communicate kar sakte hain.
